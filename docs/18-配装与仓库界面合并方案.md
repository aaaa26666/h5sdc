# M6 配装/仓库界面合并 + 装备容量化 方案

> 需求（制作人，2026-10-13）：
> ① 配装页与仓库页**合并**，左配装右仓库，配装以**可视化图案**呈现；
> ② 仓库内左键**自由拖动**物品；拖动中按 **R 旋转 90°**；
> ③ 可从仓库直接把**武器 / 护甲 / 背包 / 弹挂**拖到身上；
> ④ **背包与弹挂真做**（容量驱动局内）；**弹药与消耗品也网格化**（每格一盒、上限 60）；
> ⑤ 旧的下拉框配装表单**换掉**。

---

## 一、现状与依赖【实测】

| 项 | 现状 |
|---|---|
| 槽位 | `primary` / `secondary` / `body` / `head` 可用；`backpack` 是 `disabled` 且 `accepts: []`；**`rig`（弹挂）完全不存在** |
| 局内背包容量 | 写死在 `loot.json.backpack`（6×5 / 22kg），**与装备无关** |
| 弹药/消耗品 | **物品本身已是网格形状**：弹药全 1×1 / stack 60、绷带 1×1、急救包 2×1 —— 数据层已就绪 |
| 配装层 | 仍是**抽象计数**（`ammo: {9mm: 60}`、`consumables: {bandage: 3}`），不占格 |
| 旋转 | `core/packing.js` **已支持 90°**（`packGrid` / `findSlot` 都试两个朝向，结果记 `rotated`） |
| 仓库条目 | 已是 `{uid, itemId, count, x, y, rotated}`，UI 已按坐标绝对定位 → **拖放的底子已经具备** |

**结论**：数据层比预想的完整（弹药形状、旋转、坐标都在）。真正的工作量在三处：
**新类别 + 槽位**、**局内容量来源改造**、**界面重做**。

## 二、★ 必须先说的经济影响

`loot.json.backpack` 的 6×5 / 22kg **不是随手定的** —— 表里 `_resizeNote` 写着：
它由 6×4 调成 6×5，正是因为加入形状约束后二维排放会留空隙、同样格数装到的价值下降约 18%，
导致「正常档」中位收益跌出设计目标区间。**即：这组数字是被经济目标区间反推出来的。**

一旦"容量由装备决定"，`tools/validate-loot-tables.mjs` 的蒙特卡洛模拟（它按单一固定容量装包）
就必须声明**按哪个包装包**。处理方式：

> **把 `loot.json.backpack` 重新定位为「参考装载」** —— 校验器继续用它模拟（既有校准不被破坏），
> 同时它也是**玩家未装备背包时的兜底**（新号空手进局仍能拿东西）。
> 装备了背包/弹挂时，容量与负重以**装备**为准。

这样：既有经济校准保住；"更大的背包"才有意义（且成本体现在重量与价格上）。

## 三、设计

### 3.1 新的物品类别与槽位

| 类别 | 字段 | 槽位 |
|---|---|---|
| `backpack` | `capacityW/capacityH`（网格）、`weightLimitKg` | 启用 `backpack` 槽（`accepts: ["backpack"]`） |
| `rig` | `capacityW/capacityH` | **新增** `rig` 槽（`accepts: ["rig"]`） |

- 新增 3 个背包（小/中/大）+ 2 个弹挂，作为 `loot.json` 物品与商店条目
- **新类别必须同时进 `economy.priceRules.sellRatio`**（启动期强校验），否则报错

### 3.2 局内：容量来自装备，弹药与消耗品进网格（销 M5-TEMP-11）

- `raidKit` 不再带 `ammo: {口径: 发数}` 与 `consumables: {id: 数量}`，改为
  **把物品放进背包网格**（各带自己的格子坐标）
- 备弹数 = 网格里该口径弹药的总发数（`weapon.reserve` 因此变成派生量）
- 弹挂给一个**独立网格**（弹匣/药品），与背包并存

### 3.3 界面：合并面板 + 可视化 + 拖放

- 页签由 5 个变 4 个：**装备（配装+仓库）/ 商店 / 技能 / 任务**
- 左：人形剪影 + 装备格（头/身/主武器/副武器/背包/弹挂）+ 负重条
- 右：仓库网格（沿用现有绝对定位的格子渲染）
- **拖放**：`pointerdown` 起拖 → 跟随指针的幽灵元素 → `pointerup` 落位
  - 仓库内自由拖动：落点用 `packing.js` 的碰撞规则判合法，非法则**回原位**
  - 拖到装备格：按 `accepts` 白名单判定；非法则回原位并给出原因
- **拖动中按 R 旋转**：交换 w/h，幽灵元素实时换形；非法朝向落点用红色提示

## 四、分批实施

1. **数据层**：`backpack` / `rig` 类别与物品、启用背包槽、新增弹挂槽、经济类别、校验与断言

3. **界面层**：合并面板、可视化配装、拖放与旋转、端到端

## 五、风险

| 风险 | 说明 |
|---|---|
| **弹药网格化触及三个局内模块** | `weapon.js`（备弹）、`player.js`（消耗品）、`inventory.js`（容量）。换弹/备弹口径会变，且**弹药占格后"带多少发"成为真取舍** —— 会改变交火可持续性，进而影响 M6-6 的难度曲线 |
| **两条网格并存** | 背包 + 弹挂两个网格，"这件东西该进哪个"需要明确规则（弹挂只收特定类别？），否则玩家会困惑 |
| **拖放的自动化验证易碎** | puppeteer 的指针拖放在无头下要分多步派发；断言要落在**状态变化**（坐标/装备）上，而不是幽灵元素的位置 |
| **旧配装表单删掉** | `panels.js` 的 `renderLoadout` 与相关 `data-act` 处理器要一并移除，不能留"看起来还能用"的死入口 |
