## 一、一句话结果

配装与仓库**合并为一个「装备」页**：左侧人形剪影 + 六个装备格（头/身/主武器/副武器/背包/弹挂）+ 负重条，

## 三、★ 三处裁定（都写进了代码注释，不只是文档）

### 3.1 页签是 **6 → 4**，不是方案写的 5 → 4 —— 简报不能删

**事实**：`src/ui/lobby.js` 原本有 **6** 个页签（`brief / loadout / stash / shop / skills / quests`），
而 `docs/18` §3.3 写的是"5 个变 4 个" —— 方案**少数了一个**（漏掉 `brief`）。

**裁定（本批次做的）**：简报**并入「装备」页顶部**（`#lobbyBody` 原样保留、`.brief-strip`），
页签总数 6 → 4。理由：简报里有进战区前**唯一**的权威信息 ——

- 地图与层数、单局时限、资源分区与容器数、敌方数量与分级；
- **撤离点及其开放规则**（常驻 / 时间门槛 / 时间窗 / 击杀门槛）。

删掉它等于**静默丢信息**：玩家进战区前看不到撤离点规则，而这正是 `docs/18` §五 点名要避免的
"看起来更简洁、实际少了东西"。因此这条偏差必须显式记录，而不是让它变成一条无人知道的差异。

配套：默认页签由写死的 `'brief'` 改为 `TABS[0]`（少一处"页签列表"的副本）。

### 3.2 装备格 ↔ 装备格**不做互换**

需要两件装备同时换手，而界面上没有第二个落点可预览"换完之后长什么样"。
宁可多一步（先拖回仓库、再拖上去），也不要一次难以撤销的连带变化。
拒绝时返回 `slot-to-slot`，文案是"装备格之间不能直接互换（先拖回仓库再拖上来）"。

### 3.3 弹药/消耗品的 ± 计数保留

`docs/18` §3.3 要换掉的是**装备下拉框**，不是"带多少弹药"。带多少发/多少个是**真实取舍**
（火力/续航 vs 负重 vs 库存），因此保留，并把两处重复的行模板合并成一个生成器。

## 四、实现要点与守住的不变式

| 不变式 | 落地 | 为什么必须这样 |
|---|---|---|
| **判定与落库是同一条路径** | `core/dragDrop.js` 只暴露一个入口 `dropItem(..., {dryRun})`；`main.js` 的 `dropPreview` / `dropCommit` 是同一个 `dragDrop()` 加 `dryRun` 的两个薄壳 | 否则会出现"看着能放、一松手又弹回去"，或更糟的"看着不能放、松手却改了数据"。这类缺陷**极难从界面截图判断** |
| **界面里零碰撞运算** | `ui/dragdrop.js` 只做"指针 → 格坐标、幽灵元素、按 R 换形、手势区分"；落点判定全部下推到 `stashMoveTo` / `stashAddAt` / `slotAcceptsItem` / `equipFromStash` / `unequipToStash` | 界面里另写一段双层循环就会出现两套边界规则（越界算不算、旋转后的 w/h 用哪个），迟早分叉 |
| **拖放的 DOM 钩子同根** | `data-drop-slot`（左）与 `data-drop-grid`（右）都在 `#tabGear` 内；拖放层的 `root: el.gear` | 若两者落在并列面板里，拖动会"看得见却落不下"（`root.contains(node)` 把事件挡掉） |
| **格宽只有一个真值** | 布局（`panels.js` 的 `calc(var(--cell) * …)`）与判定（`ui/dragdrop.js` 读 `--cell`）都取 `index.html` 的 CSS 变量 | 两处各记一个格子尺寸会表现为"拖歪一格"，而它只在小尺寸/缩放下暴露 |
| **失败必有可读原因** | `reasonText()` 覆盖拖放可能产生的**全部**机器串，含参数化的 `slot-rejects:武器/护具/背包/弹挂` | `[M6-BUG-01]` 的教训：失败静默时玩家只能猜，而"猜"会把设计问题当成 bug |
| **拖动 vs 点选** | `CLICK_SLOP_PX = 4` 的位移阈值 | 仓库的批量出售靠点选条目；不做阈值区分就会"拖动时手抖 1px → 退化成切换选中"，玩家只看到"拖不动" |
| **不用 `setPointerCapture`** | 在 `window` 上听 `pointermove/pointerup`，并用 `blur` 兜底 | 端到端在无头下派发的是**合成** `PointerEvent`，不是活跃指针，`setPointerCapture` 会抛 `NotFoundError` |

### 4.1 DEV 夹具与 `FORBIDDEN` 清单的口径（本批次纠过一次）

`tools/verify-prod-bundle.mjs` 的 `FORBIDDEN` 语义是"这些字符串**必须不存在**于生产产物中"，
因此它**只能列 DEV-only 的夹具/接口名**（`__m2`、`teleportNearAi`、`grantWeapon`、`freeStashSpot` …）。

本批次新增的 `__m2` 夹具只有 **`freeStashSpot`** 一个（已列入）。而
`dropPreview` / `dropCommit` / `dropReject` 是 `createPanels(handlers)` 的**回调键**，
行号在 `if (import.meta.env.DEV)` **之前** —— 它们是**产品代码**，本来就该出现在产物里，
列进 `FORBIDDEN` 会让门禁立刻误报。`__m2.lobby()` 里的 `drag: panels.drag.state()` 同理
（它是 DEV 门控内返回值的字段，不是夹具名；且 `drag` 是产品词，列进去必然误报）。

区分办法是**看行号与门控位置**，不是看名字像不像夹具 —— 这条已记录在此，免得下次再踩。

## 五、独立核查（父会话做的，与它的单测互为对照）

用一次性脚本（`results/archive/dragdrop-check.mjs`，gitignored，不入库）对拖放核心做性质核查：

```
逐例：preview 与 commit 的判定必须一致（ok 与 reason 都要相同）
  ✓ 仓库→仓库 落到空格 / ✓ 原地旋转 / ✓ 落到被占格 occupied / ✓ 越界 out-of-bounds
  ✓ 仓库→装备格 背包 / ✓ 主武器 / ✓ 胸甲→头盔 wrong-cover / ✓ 弹药→背包 not-equipment
  ✓ 装备格→装备格 slot-to-slot / ✓ 没落在任何地方 no-target / ✓ 未知 uid / ✓ 未知落点类型
不一致 0 例；入参被改动 0 次
成功路径：背包槽=bp_small、该 uid 已离开仓库、仓库已用格 21→17（bp_small 恰好 4 格）✓
dryRun 从不返回新档案；commit 成功必返回新档案 ✓
```

语义确认（不是问题）：弹药拖到装备格返回 `not-equipment` 而不是 `slot-rejects:ammo`
—— 弹药根本不是装备（`equipmentIdOfItem` 返回 null），文案"这件东西不能装备"是对的。

## 八、诚实说明（没做到的）

- **真人试玩仍然是零次**。本批次交付的是"可操作"与"判定正确"；**拖动手感**
  （抓取偏移是否自然、R 旋转是否顺手、4px 阈值是否合适）**没有任何依据**。
- **`M6-TEMP-1` 没有销**：拖放只覆盖 **仓库 ↔ 装备格**；弹药/药品在**背包/弹挂网格里的落点**
  仍由算法决定（弹挂优先、大件优先）。"把手动落点存进预设"是 docs/19 就登记的原意，**本批次未完成**。
- **落点判定的覆盖边界**（裁定或未做，见 §3.2 与 §七）：装备格 ↔ 装备格不互换；
  局内背包网格仍不可拖；多选批量拖动、拖到"垃圾桶/出售"手势**均未做**。
- **自动化验证的四个脆弱点**已如实登记为 `M6-TEMP-8`：幽灵元素**像素位置没有断言**
  （只有状态/class/形状，所以"画歪了"只能靠人眼）；端到端用的是**合成 `PointerEvent`**
  （真实鼠标在高 DPI / 多显示器 / 窗口边缘未测）；拖动中的断言依赖"还没松手"，
  慢机器上事件乱序会误报（**未做重试**）；4px 阈值未标定。
- **触屏实际不可用**（未设 `touch-action`，大厅卡片内部滚动会抢手势）—— 属 M8，登记 `M6-TEMP-5`。
- **装备页需轻微滚动**才能同时看到仓库底部与底部按钮（固定像素布局，未做响应式压缩）—— 登记 `M6-TEMP-7`。
- **`--only=m5` 的一个权宜**：新组名写成「★ M6-3 / M5-3 装备页（配装＋仓库合并）拖放」，
  因为 `m5Group` 是按**组名子串**过滤的 —— 不带 `M5` 就会被 `--only=m5` 跳过
  （这正是 `--only=m5` 跑不到 M6-1/M6-2 与 M6 携行具那几组的原因）。它有效（96/96 且含新组），
