### 5.1 M3-BUG-01：两层地图上"玩家穿进墙体"的判据本身是错的

| 项 | 内容 |
|---|---|
| 编号 | **M3-BUG-01** |
| 分级 | **S3** —— 它不是玩法缺陷，是**验收判据缺陷**：会让 DoD 的十局稳定性测试报出并不存在的问题 |
| 发现于 | M3 收尾复查（M3-1b-2 ④ 之后） |
| 位置 | `src/main.js` 的调试快照（`player.cellBlocked`）、`tools/smoke.mjs` 十局稳定性判据 |

#### 现象

`tools/smoke.mjs` 的十局稳定性测试（M2 DoD：连续 10 局无致命问题）里有一条判据：

```js
if (s.player.cellBlocked) FATAL.push(`第${i}局：玩家穿进墙体`);
```

而 `cellBlocked` 来自 `level.isBlockedCell(cx, cz)`，它是**第 0 层的快照**（`blocked[]`
只由第 0 层的墙体矩形派生）。两层地图上"一层是墙、二层是楼面"是常态（楼板压墙，
见 `src/config/index.js` 与 `src/level/level.js` 的说明）——站在这种格上的二层玩家
会被判成"在墙里"。

实测（`tv_station_01`）：**44 个二层容器里有 6 个正落在"一层是墙"的格上**
（格 (11,36) (6,23) (9,23) (18,2) (5,3) (3,23)）。地图表保证这些容器格在二层
既不落墙里也不悬空，所以它们是完全正常的站位。

也就是说：**只要试玩或测试走到这些容器旁边，这条 DoD 判据就会误报。**
更糟的是它"看起来"是一条硬证据（"玩家穿墙"），会把人引向一个不存在的碰撞缺陷。

#### 根因

把"这一格在本层是不是实心"（站位合法性问题）与"玩家的身体有没有插进实体"
（穿模问题）当成了同一件事，而前者的实现只认第 0 层。

#### 为什么此前全绿

和 M3-1b-2 ④ 那次（183/183 全绿却漏掉隔层搜箱）是同一类：

| 断言 | 为什么是绿的 |
|---|---|
| 十局稳定性测试 | `teleportToContainer()` 当时**没有层参数**，永远把玩家送到一层；而列表最前面的容器都在一层 —— 二层那 44 个容器从来没有被这条测试走到过 |
| 纯逻辑单测 | 它测的是 `loot.update` / `extract.update` 的返回值，不经过 `main.js` 的快照 |
| 地图校验（render-map） | 它校验的是**地图表内部**（容器不落墙里、有楼板），与运行时的判据不是同一个对象 |

#### 修复

1. `src/main.js`：拆成两个字段，语义各自明确
   - `cellBlocked` —— "这一格在本层是不是实心"（保留原义，仍是单层快照，供诊断）；
   - `embedded` —— "脚底是否插在本格的实体跨度内部"，按 `level.spanRange()` 查
     **全部跨度**，坡道格交给表面插值（坡面不是盒子）。
2. `tools/smoke.mjs`：十局致命判据改用 `embedded`。
3. `tools/smoke.mjs`：新增「M3-BUG-01 两层站位判据」组（3 条断言），
   夹具**主动扫描**所有二层容器格并挑出 `cellBlocked && !embedded` 的那些 ——
   随机抽一个容器是测不到这条缺陷的（6/44 的概率）。
4. 顺带修掉同一根因的两个夹具缺陷（它们让 M3 的端到端覆盖停在了一层）：
   - `teleport(x, z, floor)` 增加层参数（此前写死 `y = 0`）；
   - `teleportToContainer(floor)` 增加层参数并把它传给 `teleport`；
     新增 `debugContainerList()` 暴露容器层号，供夹具按层选取。

#### 证据链

| 环节 | 证据 |
|---|---|
| 缺陷真实存在 | 44 个二层容器格中 6 个"一层是墙"；旧判据（`isBlockedCell`）在这 6 个格上**全部**报 true，新判据（`embedded`）**全部**报 false |
| 修复有效 | `node tools/smoke.mjs` → **112/112**（新增 3 条 + 「M3 二层闭环」4 条），其中新增组明确报出 `cellBlocked=true 而 embedded=false` 的格 |
| 不误伤 | `node tools/unit-tests.mjs` 218/218；十局稳定性测试（改用 `embedded` 后）仍全绿 |
| 单层行为不变 | 单层地图 `floorCount===1`，跨度表与旧的 `blocked[]` 逐格一致（已有断言），`embedded` 在单层下等价于旧判据的语义 |

#### 尚未验证

- `embedded` 的阈值（脚底在跨度内且跨度向上延伸 ≥0.2m）是**判据设计**，不是实测标定；
  真实穿模是否会出现"脚底正好贴着跨度下沿"的形态，没有构造过用例。
- 本次没有重测**性能**：`embedded` 只在快照（调试接口）里算，不在每帧主循环路径上。
