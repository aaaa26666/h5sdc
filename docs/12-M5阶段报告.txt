第 2 章  制作人裁定清单（本阶段全部取舍都有记录）
--------------------------------------------------------------------------------
本阶段实行"遇到需要抉择的地方一律先提问、等裁定"的纪律。裁定如下：

【数值】
 1. 起始货币 20000（制作人给定；我原先自拟 8000）
 2. 仓库 10×12 = 120 格；买卖价差按我提交的表；商店 15 条与解锁等级按我提交的表
 3. 通胀监控：窗口 20 局 / 通胀比 1.35 / 通缩比 0.5
 4. 起始配装：**只给 P9 手枪 + 二级甲 + 二级头盔 + 9mm 60 发 + 绷带 3 + 急救包 2**
    （明确不给长枪 —— 首局只有手枪面对 7 名 AI，难度显著更高，这是刻意选择）
 5. 弹药"一格最多堆叠 60 发"；霰弹（12ga）原先没有物品条目 → 新增"12 号霰弹"并进掉落池
 6. 负重三档：<20kg 正常 / 20~30kg 移速 ×0.8 不禁冲刺 / 30~40kg ×0.6 禁冲刺 /
    ≥40kg ×0.4 禁冲刺（第二档的 ×0.8 是笔误，已确认为 ×0.6）
 7. 弹药与消耗品**不设数量上限**；由仓库供给（进局扣 / 撤离还剩余 / 阵亡全丢）
 8. 等级曲线 base 900 / growth 1.05 / 满级 30（约 87 局满级）
 9. 技能点：满级恰好够点满全树（29 点）；技能效果**翻倍**
10. 技能与任务**全部取消等级门槛**（任务保留前置链；技能之间也不再互相依赖）
11. 洗点要做，且要花货币：每已花点数 1500，全额退还
12. 任务奖励与目标数值按我提交的表（5 条任务，覆盖五类目标）
13. 新账号仓库**为空**（不预置起始装备，玩家自己买）；允许缺件进局，且**不做缺件提示**
14. 装备耐久与弹匣不做局外持久化（登记 M5-TEMP-9/10）；弹药/消耗品暂不占网格（M5-TEMP-11）

【表现与流程】
15. 大厅改为**标签页**（简报 / 配装 / 仓库 / 商店 / 技能 / 任务）
16. 结算页补：经验与升级 + 任务进度 + 仓库入库明细（含"未存入清单"）
17. 数量输入用 +/- 按钮（弹药一次一格，消耗品一次一个）
18. 任务**手动接取**；阵亡局推进击杀/开箱类，收集类与撤离类只在成功撤离时推进
18b. ★追加裁定：**前置任务必须"完成并领取奖励"之后，下一段才可接取**
    （只完成未领奖**不算** —— 领奖因此是任务链上的必经一步，而不是可拖到最后一起点的收尾动作。
     界面在锁定时显示"需先完成并领取「活着回来」的奖励"，把人话与前置任务名一并给出）
19. 局内 HUD 任务追踪**全部列出**（最多 maxActive 行）
20. 画质三档：阴影关+像素比 1.0 / 1024+1.5 / 2048+2.0；大厅与局内都能改，**立即生效**
21. 音乐轨接上空总线（BGM 属 M7）
22. 改键：**移动类固定不可改**（前后左右/冲刺/蹲下/跳跃），其余 8 个动作可改；
    **仅大厅可改键**；鼠标键不纳入（转 M6）
23. 触屏控件 M5 不做（转 M8）；触屏设备**不做提示**
24. 冒烟测试并入 tools/smoke.mjs，并支持 `--only=m5`
25. 先出阶段报告，README 等收尾后再改

三条纪律（都有断言或静态检查守着）：
  1. **不双向耦合**：core/ 与 platform/ 的新增文件不 import gameplay/level/render/three。
     ui/lobby.js 的 import 由冒烟静态检查扫描（禁止出现 gameplay|level|render|audio）。
  2. **单一数据源**：价格只在 core/shop.js；负重只在 core/loadout.js；等级只在
     core/progression.js；伤害解算仍只有一处。跨表的重复字段（装备的重量/估值/形状）
     在**启动期**交叉校验，不一致直接拒启动。
  3. **幂等落库**：core/settlement.js 是纯函数，档案里的 lastRaidId 是幂等键。

M5 硬性要求的**实测**证据（都在真实浏览器、真实 localStorage 上）
  ① 存档损坏：写入 `{"version":1,"stash":[` → 页面不崩、仍进大厅、给出可用档案；
     坏文本被写进隔离键（`quarantine.reason = "bad-json"`，含原文，可供人工恢复）。
  ② 存档被清空：清掉档案键 → 新档案（Lv1 / 空仓库）；第一次加载记账 `empty`；
     重进后仍是全新档案、不留半坏状态。
  ③ 版本回退：写入 `{"version":99,...}` → **拒绝解释**，另起新档；
     原始文本留在隔离键（`reason = "version-ahead:v99>v1"`），且**不会**把未来版本
     的数据按旧规则写回去（货币没有被写成 123456）。
  ④ 幂等：同一 raidId 第二次提交直接返回原档案（不累加）；单测另有 3 条覆盖。
  ⑤ 配装进局一致性：大厅改主武器 → 局内 `weapon.id` 随之改变；护甲与弹药储备同源；
     进局扣件清单非空（撤离要把没用完的还回来）。
  ⑥ 技能真实生效：学会"负重训练"后，局内背包负重上限 22 → 28 kg（不是只改界面数字）。
  ⑦ 画质真的装上：低档 `shadows=false, pixelRatio=1`；高档 `shadowMapSize=2048`
     （尺寸变更必须真的重建 shadow map，否则是"看不见的假生效"）。
  ⑧ 改键真的生效：改到 T 后立即生效；移动类被拒；Ctrl 组合被拒（约束 C-19）。
  ⑨ 任务链需领奖才解锁：接取 q1 → 成功撤离（完成）→ 下一段**仍锁着**且面板显示
     "需先完成并领取「活着回来」的奖励" → 领奖 → 下一段变为**可接取**。

★ 一处测试陷阱（**不是产品缺陷**，记下来避免下次重复怀疑）
  端到端在"回大厅后立刻再进战区"时，曾出现"撤离倒计时卡在 0.5 秒、局内时间几乎不推进"。
  读数：`paused=true`、`remainingMs` 40 秒只减几百毫秒、玩家坐标**恰好在撤离区圆心**、
  朝向/血量正常。根因是 **Chrome 在 `exitPointerLock()` 之后约 1 秒内会拒绝新的指针锁定
  请求**，而夹具的点击间隔只有约 600ms → 锁定被静默拒绝 → 游戏按设计进入**暂停态**，
  局内逻辑（含撤离倒计时）不推进。
  这是浏览器的行为，不是游戏的问题（真实玩家点击间隔远大于 1 秒；"未锁定即暂停"本身
  是正确的产品行为）。已把它固化进测试：`smoke.mjs` 新增 `startRaidFromLobby()`，
  开局前留出冷却、开局后等待锁定，失败再走 `ensureRunning()` 兜底。


第 5 章  缺陷登记（详见 docs/M5-TEMP-REGISTRY.md 第九节）
--------------------------------------------------------------------------------
M5-BUG-03（S2）局内直接"返回大厅"会静默丢装备
    M5-3 引入"进局扣件 / 结算还件"之后，"回大厅"多了一个前提：必须先结算。
    原 returnToLobby 在 RAID 状态下直接拆世界 —— 扣掉的配装既不还回也没有结算记录。
    修复：RAID 状态下先按「放弃本局」结算。发现者是**新增的冒烟组**（它会走非常规路径）。
M5-BUG-04（S2）取件清单被跨局复位清掉
    resetRaidState() 是 enterRaidWorld() 的第一步，而 startRaid() 先 takeLoadout 再
    enterRaidWorld —— 刚写好的 raidTaken 立刻被清空（撤离还不回、阵亡不计损失）。
    修复：把 raidTaken 从 resetRaidState 移出（它是"本局的输入"，不是跨局残留）。
M5-BUG-05（S3）空档案路径的 repairs 不可观测
    parseProfile 的空档案分支没把 `_repairs` 挂到档案上，于是"存档曾经是空的"这件事
    在界面与 DEV 接口里都读不到。修复：该分支也写 `_repairs`。
附带修正一例断言口径错：原写"清空后重进仍要有 repairs" —— 第一次加载已把新档写回，
第二次读到的是一份合法档案，自然无可修。断言已改为"仍是全新档案、不留半坏状态"。

本阶段还有 4 处**断言口径错**（不是产品缺陷，记录以免重复怀疑）：
  · 起始弹药断言原先假设"与 M2 逐字段一致"，制作人裁定改配装后失效 → 已按裁定重写；
  · 报文的"任务追踪"原先断言占位值存在，改为断言"没有进行中任务时显示 任务 —"；
  · `bindings` 是整表覆盖，"只提交一个非法项"的结果是该动作回落默认而不是保留旧值；
  · 换枪测试原先选了 smg_v9（slot:2，属副武器槽）—— 界面按槽位过滤，选择被正确拒绝。

第 7 章  已知限制与风险
--------------------------------------------------------------------------------
1. **数值全部未经试玩标定**。本阶段的数值（等级曲线、技能效果、负重阈值、任务目标、
   经济价差、任务奖励）都是"看起来合理"的取值，机制正确性有断言守着，**手感与平衡性
   没有依据**。已登记的标定入口：每张表的 `_note` 字段都写了"改它只改这一行"。
2. **触屏不可玩**（控件转 M8）。检测到粗指针设备时不做任何提示（制作人裁定）。
3. **存档只有本地一份**（纯 PVE 单机）。写入前会把上一份拷进备份键，加载失败时按
   "主键 → 备份 → 新档"回落；但仍无法抵御"清浏览器数据"这类外部行为。
4. **配装扣件的时机**是"进局即扣"。若玩家在局内被强杀（进程被 kill 且 pagehide 未触发），
   这一局会按"未撤离"补结算 → 配装丢失。这与 M4-7 的口径一致（未撤离 = 只保安全箱），
   但代价是"一次异常退出丢一套装备"，比 M4 更痛。
5. **首包体积余量只剩 15.4 KB**（184.6 / 200 brotli）。M6 扩充内容前需要先决定：
   是否放宽预算、或做代码分割（本阶段已用掉 M5 的全部余量）。
6. 洗点没有二次确认以外的限制（例如冷却），而它是可反复的操作。
