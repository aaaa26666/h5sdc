## 分类解读

### 必须优先处理的（影响 M2 玩法质量或存在正确性风险）

- **M1-TEMP-16（隔墙命中）**：这是**正确性缺陷**，不是体验问题。
  从墙上方斜射的子弹会穿过墙体打中敌人。M2 做掩体玩法前必须修，否则掩体不可信。
- **M1-TEMP-18（探头目前没有战术价值）**：探头只移动相机，**不改变 AI 眼中的命中体积**，
  所以"探头出去被打中的概率与站着不动完全一样"。这个功能**目前是半成品** ——
  玩家会感觉"探头没用"，而真实原因是暴露面积没变，不是参数没调好。
  M2 必须连同 AI 命中判定一起改，否则这个功能等于装饰。
- **M1-TEMP-6（无寻路）**：AI 会卡在墙上，直接导致交战体验不成立。
  M0-5 已经给出方案与硬约束（C-1/C-2），M2 直接接。
- **M1-TEMP-2 / M1-TEMP-3（移动手感与台阶）**：M2 的主题就是手感，这两项是主体。
- **M1-TEMP-4（武器结构化）**：M2 要扩充武器，必须先结构化。
- **M1-TEMP-15（调试接口）**：留在代码里等于把内部状态暴露给任意页面脚本，
  M2 必须移除并改建正式测试设施。

### 可以推迟的

- M1-TEMP-11、M1-TEMP-13（表现与规则细化）属打磨项。
- M1-TEMP-10（背包系统）按《流程文档》属 M3 范围，M2 不必提前做。

## 按键绑定事故（必读，M2 起做输入映射层前先看）

**事故一（浏览器保留键）**：M1 曾把"蹲下"绑定到 Ctrl。玩家蹲下前进 = **Ctrl+W = 关闭标签页**，
在 Chromium 系浏览器（含 QQ 浏览器）上可复现，且**游戏无法拦截**。

**事故二（重复绑定）**：加入左右探头时，`leanRight` 绑了 KeyE，
而 `interact`（搜索容器）**本来就是 KeyE** —— 一次按键同时触发"右探头"和"搜刮"。
搜刮已改为 **KeyF**。

**机理（事故一）**：浏览器保留快捷键由浏览器 UI 层处理，不走页面的可取消路径，
`preventDefault()` 对它们无效。页面唯一能做的防御是**不绑定这些组合**。

**已固化**：
- 绑定表集中在 `src/platform/input.js` 的 `DEFAULT_BINDINGS`
  （蹲下 = `KeyC`、交互 = `KeyF`、探头 = `Q`/`E`）
- 平台约束 **C-18**：游戏动作键严禁绑定 Ctrl / Alt / Meta
- 平台约束 **C-19**：按键自定义 UI 必须拒绝 Ctrl/Alt/Meta 组合
- 平台约束 **C-21**：同一按键不得绑定到多个动作（改键 UI 亦须校验）
- 静态审计 `tools/audit-keybindings.mjs` 两条规则：
  规则 1 修饰键、规则 2 重复占用。两条均已做**注入自检**，确认违规时会 exit 1

**为什么这两条都必须写进清单**：
1. CDP 合成的按键走渲染进程，**不会触发浏览器 UI 快捷键**，
   所以事故一那类缺陷**自动化冒烟测试天然抓不到**。
2. 事故二暴露了一个更普遍的问题：**事故一之后我建了审计，但审计只查修饰键**，
   于是重复绑定发生时审计全绿。**"有一个检查器"不等于"问题被覆盖"** ——
   新增键位时必须同步扩检查项。
