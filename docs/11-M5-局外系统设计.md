## 1. 总体架构与分层

```
                     ┌──────────────── 局外（本阶段新增）────────────────┐
  localStorage ──► platform/profileStore.js ──► core/profile.js（纯）
   （存档）          备份 / 回滚 / 损坏隔离        版本 + 迁移 + sanitize
                                                        │
                    ┌───────────────────────────────────┴───────────────┐
                    ▼                    ▼                ▼             ▼
            core/stash.js        core/loadout.js    core/progression  core/quests.js
            （格子/堆叠/排序/     （槽位/负重/预设）  .js（等级/技能）   （进度/奖励）
              批量出售）                │                │             │
                    └──────────────┬────┴────────────────┴─────────────┘
                                   ▼
                          core/shop.js（价格唯一算法）
                                   │
                     ui/*.js（只排版，不算数）──► index.html 面板
                                   │
                    ┌──────────────┴───────────────┐
                    ▼                              ▼
        raidKit（配装 + 技能倍率 + 任务追踪）   结算回写（幂等）
                    │                              ▲
                    ▼                              │
        ────────── 局内（既有系统，只读取 raidKit）──────────
        inventory / player / weapon / loot / hud / quest 追踪
```

三条硬纪律（对应 M5 约束词的「禁止」段）：

1. **不双向耦合**：`src/core/*` 与 `src/platform/*` 的新增文件**不得 import** `src/gameplay/*`、`src/level/*`、
   `src/render/*`、`three`。局外系统通过 `raidKit` 这一份**数据结构**与局内交互，
   而不是通过函数调用。这条由 `tools/smoke.mjs` 的静态检查（扫 import 行）守住，不靠自觉。
2. **单一数据源**：价格只在 `core/shop.js` 算；负重只在 `core/loadout.js` 算；
   等级只在 `core/progression.js` 算。UI 层出现的每个数字都来自这些纯函数或配置表，
   `ui/` 下的文件里不允许出现参与计算的数字字面量（沿用 M5-1 对 `ui/lobby.js` 的断言口径）。
3. **幂等落库**：一局只结算一次。`applyRaidToProfile()` 是纯函数，
   且档案里记录 `lastRaidId`；同一个 `raidId` 第二次提交直接返回原档案（不累加）。

## 2. M5-7 存档系统

### 目的
把玩家的局外进度（等级、货币、仓库、配装、任务、统计）持久化，且**任何异常情况下都不崩、不静默丢档**。

### 输入输出
| 函数 | 输入 | 输出 |
|---|---|---|
| `createNewProfile(cfg)` | 配置 | 一份全新档案（新账号） |
| `sanitizeProfile(raw, cfg)` | 任意 JSON 值 | `{ profile, repairs[] }` —— 逐字段校验后的档案 + 修复记录 |
| `migrateProfile(raw, cfg)` | 任意 JSON 值 | `{ profile, fromVersion, applied[] }` |
| `saveProfile(p)` / `loadProfile()` | —— | `platform/profileStore.js` 提供，localStorage |

### 档案结构（v1）
```jsonc
{
  "version": 1,
  "profileId": "p-l8x2-4f1",
  "createdAt": 0, "updatedAt": 0,
  "currency": 8000,                       // 唯一货币（§5）
  "progression": { "level": 1, "exp": 0, "skillPoints": 0, "skills": { "pack_mule": 1 } },
  "stash": [ { "uid": 1, "itemId": "bandage", "count": 3, "x": 0, "y": 0, "rotated": false } ],
  "loadouts": [ { "id": "default", "name": "默认", "primary": "rifle_m4", ... } ],
  "activeLoadoutId": "default",
  "quests": { "active": ["q1"], "progress": { "q1": { "o1": 2 } }, "completed": [], "claimed": [] },
  "stats": { "raids": 0, "extracts": 0, "deaths": 0, "kills": 0, "earned": 0, "lost": 0, "bestValue": 0 },
  "economy": { "samples": [ { "raidId": "r1", "atMs": 0, "outcome": "extract", "income": 0, "spent": 0 } ] },
  "lastRaidId": null,                     // 幂等落库的键
  "_repairs": []                          // 最近一次加载做过的修复（诊断用，非玩法数据）
}
```

### 版本与迁移
- 当前 `PROFILE_VERSION = 1`。迁移是一串**单向**步骤：`MIGRATIONS[n]` 把 v(n) 变成 v(n+1)。
- 起点 v0 是"史前结构"：M4 及以前只有本机偏好设置（`h5extract.settings.v1`）与局内快照，
  没有档案。因此 v0→v1 迁移的真实内容是：**把旧设置的字段吸收进档案的可选偏好镜像，
  并生成初始仓库/配装**。这样"迁移"不是空函数，有可断言的产物。
- 档案版本 **高于** 代码支持的版本（版本回退：玩家装回旧版本 / 手动改大 version）：
  **拒绝加载**，把原始文本原样存进隔离键 `h5_extract_profile.v<N>.quarantined`，
  返回新档案并记 `repairs += 'version-ahead'`。理由：把未来版本的数据按旧规则解释，
  比丢弃它更危险（会写出结构错乱的存档覆盖掉它）。

### 异常三态（M5 硬性要求，必须实测）
| 状态 | 注入方式 | 期望行为 |
|---|---|---|
| 损坏 | 写入 `{`或 `{"version":1,"stash":[{"itemId":123}]}` 等非法内容 | 不崩；坏文本转存隔离键；从备份恢复；无备份则新档；`repairs` 非空 |
| 被清空 | `removeItem` 两个键 | 不崩；给出全新档案；统计归零；下次保存照常写盘 |
| 版本回退 | `version = PROFILE_VERSION + 5` | 不崩；原档进隔离键；新建档可正常游戏；**不得**把隔离键覆盖掉 |

### 回滚方案
每次成功写入前，把**上一份**档案文本整体拷到 `h5_extract_profile_backup`（单份，滚动）。
加载失败时按 `主键 → 备份 → 新档` 顺序回落。这是"存档损坏有回滚方案"（DoD）的落地。

### 边界条件
- localStorage 被禁用（隐私模式）：`available=false`，全部读写降级为"本次会话内存档"，
  游戏可玩，界面顶部显示一行警告。**不得**因此抛错中断主循环。
- 配额满（写入抛 `QuotaExceededError`）：保留旧档不动（宁可少存一次，也不要写半份）。
  档案序列化后 > 阈值（`economy.stash.limits.maxBytes`）时先压缩（去掉 `_repairs`、截断 `economy.samples`）。
- 存档里出现**未知 itemId**（表删过物品）：该条目被丢弃并记 `repairs += 'unknown-item:<id>'`，
  不抛错（否则玩家一更新版本就进不去游戏）。

### 验收标准
1. `node tools/unit-tests.mjs` 覆盖：迁移链（v0→v1）、sanitize 逐字段、版本回退隔离、幂等落库。
2. `node tools/smoke.mjs` 在真实浏览器里注入三种异常，各断言"页面仍可用 + 档案被修复 + 无 console 错误"。
3. 重开页面（真实 reload）后等级 / 货币 / 仓库件数逐项一致。

## 3. M5-2 仓库系统

### 目的
局外存放带出的物资：二维格子、堆叠、排序、批量出售，并作为配装与商店的物品来源。

### 输入输出
| 函数（`core/stash.js`，纯） | 说明 |
|---|---|
| `stashAdd(stash, itemId, count, cfg)` | 堆叠优先、再找空位；放不下返回 `{ok:false, reason:'space'}` 与剩余数量 |
| `stashRemove(stash, uid, count)` | 部分移除（数量归零则删除条目） |
| `stashSort(stash, mode, cfg)` | `mode ∈ {category, rarity, value, name}`；**排序只改坐标不改内容** |
| `stashTidy(stash, cfg)` | 重排到最紧凑（复用 `core/packing.js` 的首次适配） |
| `stashValue(stash, cfg)` / `stashWeight(stash, cfg)` | 估值 / 总重 |
| `stashBulkSell(stash, uids, cfg)` | 返回 `{ removed, currency, lines[] }`，**价格由 `core/shop.js` 算** |

### 依赖
`core/packing.js`（形状与排放的唯一算法）、`core/items.js`（物品统一查询）、`core/shop.js`（卖价）。

### 边界条件
- 堆叠上限来自物品表 `stack`；`stack:1` 的装备永不合并。
- 单件物品形状大于整个仓库（不会发生，但校验器会挡住）：启动期校验每件物品 `w<=stash.w && h<=stash.h`。
- 仓库满：带出物**不静默丢弃**。`applyRaidToProfile` 返回 `overflow[]`，
  结算界面明确列出"仓库已满，以下物品未能存入"，并在下次进局前提示。
  （这是最容易写成静默丢档的地方，必须有断言。）
- 批量出售：至少 1 件；对 `quest` 类别与"已装备的预设引用"给二次确认（UI 层），
  纯函数层不做确认，只做执行。

### 验收标准
1. 单测：堆叠合并边界（正好装满 / 超出 1 件）、排序不动内容（多重集合相等）、
   批量出售金额 = 逐件卖价之和（与 `shop.sellPrice` 同源）。
2. 冒烟：搜到物品 → 撤离 → 回大厅，仓库里出现同样数量的该物品；仓库满时提示出现且物品留在结算列表里。

## 4. M5-3 配装系统

### 目的
让玩家决定带什么进战区，并让"局外算的"与"局内用的"是**同一份数据**。
（这是 `M5-TEMP-2` 的销账：现在局内用的是 `weapons.json.startLoadout` 写死的配装。）

### 输入输出
| 函数（`core/loadout.js`，纯） | 说明 |
|---|---|
| `createDefaultLoadout(cfg)` | 新账号预设（内容取自配置表的 `starterLoadout`） |
| `validateLoadout(lo, stash, cfg)` | 逐槽校验：物品存在、类别对、仓库里有、等级解锁 |
| `loadoutWeight(lo, cfg)` | 身上装备 + 弹药的重量（**唯一**负重算法） |
| `loadoutCapacity(lo, cfg)` | 背包/安全箱格数与负重上限（含技能加成） |
| `buildRaidKit(profile, cfg)` | ★ 局外→局内的唯一入口，产物见 §4.4 |
| `takeLoadoutFromStash(profile, lo, cfg)` | 进局前把装备**从仓库扣掉**（撤离找回 / 阵亡丢失由结算决定） |

### 槽位（`config/equipment.json`）
`primary` `secondary` `body` `head` `backpack` `rig` `ammo`（按口径）×N `consumables`（按 id）×N。

### 边界条件
- 主武器槽只接受 `slot:1` 武器、副武器槽只接受 `slot:2`（表里已有，启动期校验）。
- 弹药按**口径**携带，不给"任意弹药"；携带量上限 = 配置表 `maxReserveByCaliber`。
- 负重超限：**允许进局但受惩罚**（超重 → 移动速度倍率下降、不能冲刺）。
  不做"禁止进局"——那会让玩家卡在局外无法自救。惩罚曲线在表里（`overweightSpeedScale`）。
- 预设方案：最多 `maxPresets` 套（表里定）；删除预设必须保持至少一套。
- 装备的耐久是**每件独立**的（仓库里的护甲条目带 `durability`）。
  进局时按 `durability` 生成局内护甲；撤离后写回剩余耐久；阵亡则整件丢失。
  `[M5-TEMP]` 武器的弹匣内子弹**不**单独持久化（进局固定满弹匣），登记为临时实现。

### 4.4 `raidKit`（局外 → 局内的唯一数据结构）
```jsonc
{
  "loadout": { "primary": "rifle_m4", "secondary": "pistol_p9",
               "armor": { "body": { "id": "vest2", "durability": 55 }, "head": null },
               "ammo": { "5.56": 120, "9mm": 60 },
               "consumables": { "bandage": 3, "medkit": 1 },
               "backpack": { "w": 6, "h": 5 }, "safeTierId": "safe_t2" },
  "modifiers": { "weightLimitKg": 25, "moveSpeedScale": 1.04, "recoilScale": 0.92,
                 "spreadScale": 0.95, "searchSpeedScale": 1.1, "healSpeedScale": 1.05,
                 "overweightScale": 0.72 },
  "quests": [ { "id": "q2", "label": "…", "objectives": [ { "id": "o1", "text": "…", "have": 1, "need": 3 } ] } ]
}
```
- `modifiers` 由 `core/progression.js` 的 `skillModifiers(profile, cfg)` 算出（含配装的基础值），
  局内系统只**读**它，不再自行查表。每个倍率都有一条端到端断言证明它真的改变了局内行为。
- `quests` 是进局时的追踪快照，HUD 只显示它（销 `M4-TEMP-4`）。

### 验收标准
1. 单测：槽位校验矩阵、负重唯一算法、`buildRaidKit` 与 `weapons.json` 的
   `startLoadout`（新账号默认）**逐字段一致**（保证没有改变既有关卡行为）。
2. 冒烟：改配装（换主武器）→ 进局，`snapshot().weapon.id` 随之改变；
   换护甲 → 进局护甲 id 与耐久一致；**断言局内不存在第二份配装数据**
   （`raidKit.loadout` 与 `snapshot()` 读数同源）。
3. 冒烟：负重上限技能生效后，`snapshot().loot.bag.limitKg` 变大。

## 5. M5-4 商店与经济

### 目的
提供货币的入口与出口，并让买卖价差可配置、能输出通胀监控数据。

### 输入输出
| 函数（`core/shop.js`，纯） | 说明 |
|---|---|
| `basePrice(itemId, cfg)` | 物品基价（= 物品表 `value`；装备表另有 `price` 覆盖） |
| `buyPrice(itemId, cfg)` | 买入价 = `ceil(basePrice × buySpread[category])` |
| `sellPrice(itemId, cfg)` | 卖出价 = `floor(basePrice × sellRatio[category])`（**唯一**卖价算法） |
| `buy(profile, itemId, count, cfg)` | `{ok, profile', spent, lines[]}`；货币不足/等级不足/无货 → `ok:false, reason` |
| `sell(profile, uids, cfg)` | 委托 `stashBulkSell` |
| `inflationReport(profile, cfg)` | 通胀监控数据（见下） |

### 价格与价差
- `buySpread` 与 `sellRatio` **按物品类别**配置，`sellRatio < 1 ≤ buySpread`
  （启动期校验：任何类别都不得出现"卖价 ≥ 买价"，否则可以无限刷钱）。
- 商店在售清单（`economy.json.stock`）逐条给出：条目 id、数量（`-1` = 无限）、
  解锁等级。**价格不写死**在 stock 里，只写"是否覆盖基价"（`priceOverride`）。
  推论：改一次 `sellRatio` 全表生效，不存在两处各算一次价格。

### 通胀监控输出
`inflationReport` 的输入是档案里的 `economy.samples`（每局一行：收入 / 支出 / 结局）。
输出（同时是 `tools/economy-report.mjs` 写进 `results/economy-report.json` 的内容）：
```jsonc
{ "raids": 20, "netMedian": 9200, "netP90": 31000, "incomePerRaid": 12400,
  "currencyGrowthPerRaid": 3100, "targetBand": [1800, 36000],
  "verdict": "ok" | "inflation" | "deflation", "verdictReason": "…" }
```
判定口径写在表里（`economy.inflation`）：中位净收入落在 `targetBand` 内 = ok；
连续 `windowRaids` 局的中位高于带上限 `warnRatio` 倍 = inflation。

### 边界条件
- 购买扣货币与加物品**必须同一次纯函数调用完成**（避免"扣了钱没给货"的中间态）。
- 卖出不可逆；UI 二次确认。
- 不允许卖 `quest` 类别物品（任务物品），启动期校验任务奖励里不含"商店在售"的循环。
- 货币下限 0（不足即拒绝，不允许负货币）。

### 验收标准
1. 单测：`sellPrice < buyPrice` 对所有类别成立；买 N 件的总价 = 单价的 N 倍（无四舍五入漂移）；
   通胀判定在构造样本下给出三种 verdict。
2. 工具：`node tools/economy-report.mjs` 用**配置表 + 十局模拟样本**产出报告，退出码 0/1。
3. 冒烟：买一把枪 → 货币减少、仓库出现该枪；卖掉 → 货币增加、仓库消失、金额等于 `sellPrice`。

## 6. M5-5 等级与技能树

### 目的
把单局收益变成长期成长：经验 → 等级 → 技能点 → 技能效果（**效果必须在局内真实生效**）。

### 输入输出
| 函数（`core/progression.js`，纯） | 说明 |
|---|---|
| `levelFromExp(exp, cfg)` | `{ level, expInLevel, expForNext, totalForNext }`（唯一等级算法） |
| `raidExp(result, cfg)` | 一局的经验（撤离基础 + 容器 + 击杀 + 估值 + 结局惩罚） |
| `skillModifiers(profile, loadout, cfg)` | §4.4 的 `modifiers`（唯一倍率算法） |
| `canLearn(profile, skillId, cfg)` | 前置、等级、技能点、最大等级校验 |
| `learnSkill(profile, skillId, cfg)` | 扣点并升级（纯函数，返回新档案 + 效果摘要） |

### 经验规则（表驱动）
撤离成功：`base + perContainer × 开箱数 + perKill × 击杀 + perValue × floor(带出估值/1000)`；
阵亡 / 超时 / 放弃：同一公式 × `failedMultiplier`（且撤离基础项为 0）。
经验**只在正式结算时发放**（含刷新补结算），与仓库落库同一事务。

### 技能树
- 4 条分支（`gunnery` / `mobility` / `strength` / `medical`），每条 `maxTier` 层，
  节点有 `requires`（前置节点 + 等级）与 `maxLevel`。
- 效果类型是**枚举**（启动期校验），当前支持：
  `weightLimitKg`（加负重）、`moveSpeedScale`、`recoilScale`、`spreadScale`、
  `searchSpeedScale`、`healSpeedScale`、`sellBonusRatio`（卖价加成 —— 唯一影响局外的效果）。
- "技能点在升级时发放"与"技能效果聚合"都在本文件；UI 只显示。

### 边界条件
- 等级上限 `maxLevel`（表）；到顶后经验仍累加但不升级（显示"满级"）。
- 技能点不足 / 前置未满足 → 拒绝并返回原因字符串（UI 显示原因，不显示"操作失败"）。
- 洗点：**M5 不做**（登记为临时实现），避免"配点后悔"与存档复杂度。

### 验收标准
1. 单测：经验→等级在临界点上不跳级（恰好等于阈值 → 刚好升级）；技能前置矩阵；
   `skillModifiers` 的每一项都由至少一个节点驱动。
2. 冒烟：DEV 接口给足经验 → 升级 → 学一个 `weightLimitKg` 技能 → 进局读 `bag.limitKg` 验证变大。
3. 冒烟：学 `moveSpeedScale` 技能后，同一段路的移动速度读数变大（与 `moveSpeed` 基线之比 = 表里的倍率）。

## 7. M5-6 任务线

### 目的
给玩家在局内的目标（收集 / 击杀 / 撤离），并让 HUD 与结算显示真实进度。

### 输入输出
| 函数（`core/quests.js`，纯） | 说明 |
|---|---|
| `questsForLevel(profile, cfg)` | 当前可接/进行中的任务列表 |
| `acceptQuest(profile, questId, cfg)` | 接取（校验前置任务与等级） |
| `advanceQuests(profile, raidFacts, cfg)` | ★ 用一局的事实推进所有进行中任务 |
| `claimQuest(profile, questId, cfg)` | 领奖（货币 / 经验 / 物品 / 解锁安全箱档位） |
| `questTrackerView(profile, cfg)` | §4.4 的 `quests`（HUD 只读它） |

`raidFacts` 由 `buildRaidResult` 的产物加工而来（`core/raidResult.js` 不再含占位值，
销 `M4-TEMP-3`）：`{ outcome, elapsedMs, kills, killsByTier, containersOpened, containersByType,
keptItems:[{itemId,count}], keptValue, mapId, extractId }`。

### 目标类型（表里枚举）
`collect`（带出指定 itemId × N，**以带出为准**，阵亡不计）、`kill`（击杀 N，可限定 tier）、
`extract`（成功撤离 N 次 / 从指定撤离点）、`open`（开某类容器 N 个）、`value`（单局带出估值 ≥ N）。

### 边界条件
- 任务奖励的物品若超出仓库容量 → 走 §3 的 `overflow` 通道（不静默丢）。
- 任务完成即固定（不可重复领取）；`claimed` 集合是幂等键。
- 安全箱升级（`unlockSafeTier`）由任务发放，`safeContainer.tiers` 的档位顺序由配置表校验
  （销 `M3-TEMP-4` 的一半：门禁卡仍靠掉落，但"档案里记录已解锁档位"落地）。
- 任务进度在**刷新补结算**时同样推进（与幂等键 `lastRaidId` 一起，保证不重复推进）。

### 验收标准
1. 单测：三类目标各推进一次；`collect` 在阵亡时**不**计数；领奖幂等（重复调用不重复发放）。
2. 冒烟：接任务 → 进局开箱 → 撤离 → 回大厅，任务进度 = 开箱数；结算页显示真实经验与任务进度
   （`raidResult.progression` 不再是 0 占位）。
3. 冒烟：HUD 的 `#questText` 显示进行中任务的目标文本（销 `M4-TEMP-4`）。

## 8. M5-8 设置界面

### 目的
补齐设置的三个缺口：画质档位、音量分轨、按键自定义 + 触屏布局。

### 输入输出
- `tunables.settings.schema` 扩展：`graphicsQuality`（low/medium/high）、
  `sfxVolume`、`musicVolume`（与 `masterVolume` 分轨）、`touchLayout`（off/auto/on）。
- `platform/keybinds.js`（新）：`bindings` 的默认值（来自 `input.js` 的 `DEFAULT_BINDINGS`）、
  `sanitizeBindings()`（**拒绝 Ctrl/Alt/Meta 组合**，约束 C-19）、`formatKey()`。
- `ui/settings.js`（新，从 `ui/hud.js` 拆出，销 `M5-TEMP-4`）：
  设置面板独立成模块，同时供局内（暂停菜单）与局外（大厅）使用。

### 画质档位（`render/quality.js`，新）
| 档位 | 阴影 | 像素比上限 | 抗锯齿 | 目标 |
|---|---|---|---|---|
| low | 关 | 1.0 | 关（需重建 renderer） | 集显 / 移动 |
| medium | 开 1024 | 1.5 | —— | 默认 |
| high | 开 2048 | 2.0 | —— | 高配 |

抗锯齿不能在运行时切换（`WebGLRenderer` 构造参数），因此 `low` 档**不**改抗锯齿，
只改阴影与像素比，并在表里写明这条限制（避免"设置了没效果"的假象）。
档位变更后立即生效（阴影开关 + `setPixelRatio`），并记录一帧的耗时变化供断言。

### 音量分轨
`masterVolume × (sfxVolume | musicVolume)`。当前音频只有音效（无 BGM），
因此 `musicVolume` 先接到一个**存在的**总线上（`audio.buses.music`），
表里标注"BGM 属 M7"。这样分轨不是占位：音效总线真的受 `sfxVolume` 影响。

### 改键（销 `M1-TEMP-19`）
- 动作表来自 `input.js`（移动/射击/换弹/切枪/蹲/跑/跳/探头/搜索/医疗/暂停）。
- 绑定冲突：拒绝重复绑定（同一键只能属于一个动作），拒绝修饰键组合（C-19）。
- 触屏布局：`touchLayout` 打开时显示虚拟控件（左摇杆移动、右侧拖动视角、
  按钮：开火 / 开镜 / 换弹 / 蹲 / 跳 / 搜索 / 医疗 / 切枪）。控件定义表驱动（位置用百分比）。
  桌面端默认 `auto`：只有检测到粗指针（`matchMedia('(pointer: coarse)')`）才启用。

### 验收标准
1. 单测：`sanitizeBindings` 拒绝 `Ctrl/Alt/Meta` 组合、拒绝重复、未知动作被丢弃；
   键码解析与 `formatKey` 往返一致。
2. 冒烟：改键后按新键真的开火（替换默认键后旧键无效）；
   注入一个 `Ctrl+X` 绑定 → 被拒且不改动设置；画质档位切换后 `renderer` 的阴影状态随之改变。
3. `node tools/audit-keybindings.mjs` 扩展到"档案里的自定义绑定"，与默认表一起审计。

## 12. 实现与本文档的偏差（如实记录）

本文档写于**动代码之前**（《流程文档》第 7 章："禁止边写边想"）。实现过程中，一部分
因制作人裁定、一部分因更简单的实现更合适，与本文档产生了偏差。逐条列出，**以免有人
拿文档当实现的描述**：

| 本文档的写法 | 实际实现 | 原因 |
|---|---|---|
| §2 `applyRaidToProfile()` 在 `core/profile.js` | 在 **`core/settlement.js`** | profile 只负责"档案结构 + 版本 + 迁移"，结算落库是另一件事。同一个文件塞两件事会让"档案长什么样"与"一局怎么记账"互相牵制 |
| §4 槽位含 `backpack` / `rig` | 只有 `primary` / `secondary` / `body` / `head`；`backpack` 槽在表里 `disabled` 并写明原因 | 背包容量固定来自 `loot.json.backpack`，M5 没有任何可替换项。做一个只有一件可选物的槽位是**假功能**（项目纪律：不留占位入口） |
| §6 技能树有 `requires` 与 `minLevel` 门槛 | 表里**两者都没有**（校验器与 `canLearn` 仍支持这两个可选字段） | 制作人裁定"连前置依赖也取消"。全表写 `"requires": []` 就是死配置 |
| §7 任务有 `level` 等级门槛 | 表里**没有** `level` 字段 | 制作人裁定"任务全部取消等级门槛"，只保留 `requires` 前置链 |
| §7 `collect` 类目标口径 | 采纳（只在成功撤离时推进），并明确了 `extract` 同类处理 | —— |
| §8 面板拆成 `ui/stash.js` / `ui/loadout.js` / … 五个文件 | 合成 **`ui/panels.js`** 一个文件（五个 render 函数共用同一套事件委托与工具函数） | 五个面板的渲染逻辑高度同构；拆成五个文件会重复五份 esc/委托/工具栏代码。设置面板**仍然独立**成 `ui/settings.js`（它属于另一个职责层） |
| §8 触屏布局：M5 做基础可操作版 | **M5 不做控件**，只保留 `touchLayout` 设置项与能力检测的位置 | 制作人裁定 Q2（触屏控件转 M8） |
| §9 `economy.json` 里写买卖价差与商店清单 | 采纳；另外**新增** `qualityTable`（画质档位参数）到 `tunables.settings` | 画质档位是 M5-8 的交付，它的参数属于"本机偏好"表 |
| §9 跨表校验：装备与 `loot.json` 同名物品逐字段一致 | 采纳，并在启动期实现（`buildItemViews`） | 它同时产出了"物品视图"与"件↔发换算"（弹药每格 60 发） |
| §10 测试矩阵 | 采纳；另加 `--only=m5` 过滤与 `tools/economy-report.mjs` | 前者是制作人裁定 R6，后者是 M5-4 的硬性要求 |

**没有偏差的部分**（可以按本文档理解）：单一数据源的三条纪律、`raidKit` 的形状与语义、
存档的版本/迁移/异常三态口径、结算的幂等键、任务的五类目标与推进口径、
经济价格只在 `core/shop.js` 一处、界面不算数。
