第 0 章  本文档的使用方式与重要声明
--------------------------------------------------------------------------------
0.1 本文档是"准入标准"，不是"建议"
    任何资源不符合本文档的规格，**不得进入工程**。
    禁止"先接进去再优化"。超标资源一律当场退回。

0.2 数值来源标注（必须严格遵守）

    本文档每个数值有三个来源之一，必须按标注使用：

      【实测】 —— M0 阶段真实测得的数字，可直接作为依据
      【派生】 —— 由实测数据推算得出，附推算过程，须在使用中验证
      【待定】 —— M0 阶段无资源可测，**不得作为验收依据**，
                 须在指定阶段补测后填入

    凡标注【待定】的项，验收时不得引用其数值。这是 M0 硬性要求：
    "所有性能数据必须是实测数字，禁止估算。测不出就写未测。"


第 1 章  总体预算
--------------------------------------------------------------------------------
1.1 首包预算（依据《流程文档》第 9.2 节）
    硬约束：首包 ≤ 30 MB，目标区间 15 ~ 25 MB。

1.2 已占用的首包份额【实测】
    项目                              体积（brotli）
    ------------------------------------------------------
    JS 运行时（three + 应用骨架）      106.7 KB
    剩余可供资源使用                   ≈ 29.9 MB

    结论：**首包体积问题几乎全部是资源问题**，代码侧占 0.35%。

1.3 资源预算分配框架【待定】

    分项                                        预算上限      状态
    ------------------------------------------------------------------
    JS 运行时                                   2 MB br       【实测 186.6 KB（M6-1 前）】
    局外 UI 贴图与图标                          ≤ 3 MB        【待定】
    首屏字体（中文字体子集）                    ≤ 2 MB        【待定】
    首发地图进图必需资源                        ≤ 15 MB       【待定】
    音频（UI 音效 + 首段 BGM）                  ≤ 5 MB        【待定】
    预留缓冲                                    ≥ 3 MB        【待定】

1.4 中文字体是独立风险项
    完整中文字体动辄数 MB，是首包的潜在杀手。
    M1 就必须确定方案：字体子集化（按游戏实际用字生成）或按需加载。
    在方案确定前，字体预算按 ≤ 2 MB 上限控制。


第 2 章  几何与渲染规格
--------------------------------------------------------------------------------
2.1 Draw call 预算【派生】
    实测依据（M0-5，6x CPU 节流模拟低端 CPU）：
      362 个 Mesh → renderP95 16.188 ms
      712 个 Mesh → renderP95 18.058 ms
      线性拟合得：固定开销约 15.9 ms，每个 Mesh 约 0.0053 ms

    推算：60fps 预算 16.67 ms，扣除游戏逻辑与其他系统约 5 ms，剩 11.67 ms。
          但固定开销 15.9 ms 已超预算 —— **说明 312 个静态 Mesh 的未优化写法
          在低端 CPU 上直接不成立**。

    派生结论：
      - 单帧 draw call 上限：**约 200 ~ 250 个**（6x 节流下）
      - 该值必须在 M8 用真实关卡复测后修订，不得作为最终数字对外承诺

2.2 强制要求：静态几何必须合批
    【实测依据】约 312 个独立墙体 Mesh 在 6x 节流下占约 15.9 ms/帧，
    是 AI 成本的数十倍。

    规格要求：
      - 关卡静态几何**必须**实例化（InstancedMesh）或几何合并
      - 禁止逐个 Mesh 提交静态墙体、地板、掩体
      - 同一材质的静态物体必须合批

2.3 动态物体（角色、道具）规格【待定】
    以下项在 M0 无正式资源，**未测**，须在 M7 资源替换后填入：

    项目                                  上限             状态
    ------------------------------------------------------------------
    单个角色模型三角面数                  【待定】         未测
    单个武器模型三角面数                  【待定】         未测
    角色骨骼数量上限                      【待定】         未测
    同屏角色数量                          【待定】         未测
    单个场景道具三角面数                  【待定】         未测

    参考约束（来自 C-4）：同屏 AI 数量上限**暂不写死**，
    真实上限由渲染决定，须在 M7/M8 后重新测定。

2.4 LOD 要求
    【待定：具体 LOD 层级与切换距离需在 M7 依据实测帧率确定】
    强制要求：所有进入同屏渲染的角色与大型道具必须具备 LOD。


第 3 章  贴图规格
--------------------------------------------------------------------------------
3.1 传输与压缩格式（强制）
    规格要求：
      - GPU 压缩纹理：优先 KTX2（Basis Universal）或平台对应格式
      - 禁止大量未压缩 PNG/JPG 直接进首包
      - 传输层必须开 brotli（CDN 配置，见 M0-TECH-01 约束 C-11）

    【实测支撑】brotli 相对 raw 可省 80%（524.4 KB → 106.7 KB）。

3.2 尺寸上限【待定】

    项目                                  上限             状态
    ------------------------------------------------------------------
    单张 UI 贴图尺寸                      【待定】         未测
    单张场景贴图尺寸                      【待定】         未测
    单张角色贴图尺寸                      【待定】         未测
    单张贴图文件体积上限                  【待定】         未测
    首包内贴图总体积                      ≤ 15 MB          【待定】

    说明：M0 阶段**未接入纹理压缩管线**（KTX2/Basis/ASTC），
    因此无法测得真实贴图体积。**不得**引用"1024² 贴图约 0.7~1.4 MB"
    这类行业经验值作为验收依据 —— 那是估算不是实测。

3.3 贴图图集要求（强制，不依赖未测项）
    - 同类小贴图必须打图集，禁止大量独立小贴图
    - 图集尺寸必须是 2 的幂
    - UI 图标统一走图集


第 4 章  音频规格
--------------------------------------------------------------------------------
4.1 格式选择【实测】
    实测：Chrome 153 与 Edge 136 对以下格式均返回 canPlayType = "probably"：
      MP3、AAC(mp4a.40.2)、OGG Vorbis、OGG Opus、WebM Opus、FLAC、WAV(PCM)

    推荐：**OGG Opus**（压缩率最优）。
    注意：该结论仅对 Chromium 系成立。Safari 对 OGG 系列的支持历来不同，
          兼容矩阵要求覆盖 Safari，**须在 M8 补齐验证后再最终确认格式**。

4.2 解码成本【实测】
    实测：30 秒立体声 WAV（5.17 MB 未压缩 PCM）解码耗时 50 ~ 60 ms。
    注意：这是 **PCM 解码**数字。压缩格式（MP3/Opus/AAC）的解码成本**未测**，
          不得据此推断。

4.3 音频资源规格【待定】

    项目                                  上限             状态
    ------------------------------------------------------------------
    采样率                                【待定】         未测
    位深                                  【待定】         未测
    单个音效文件体积上限                  【待定】         未测
    BGM 单曲体积上限                      【待定】         未测
    首包内音频总体积                      ≤ 5 MB           【待定】
    同屏并发播放声道数上限                【待定】         未测

4.4 播放行为强制要求（不依赖未测项）
    【实测依据】无用户手势时 AudioContext.resume() 永不 settle（永久挂起）。

    规格要求：
      - 音频资源必须支持"未解锁时静默丢弃"，不得因播放失败中断游戏逻辑
      - 枪声必须分层（近距/远距/尾音），并支持距离衰减
      - 移动端首次交互限制虽本期不做移动端，但解锁门机制必须实现

4.5 音频交付要求
    - 必须提供无损源文件与压缩后的交付文件两套
    - 命名规范、目录规范、版本号规范与美术资源一致
    - 长音频（BGM）必须与短音效分目录，便于按需加载


第 5 章  内存规格
--------------------------------------------------------------------------------
5.1 已实测的 JS 堆内存【实测】

    场景                                堆内存峰值
    ------------------------------------------------------------------
    M0-3 等价场景（three，vsync=on）    14.89 MB
    M0-3 等价场景（three，vsync=off）   28.14 MB
    M0-5 AI 压测 N=50                   20.28 MB
    M0-5 AI 压测 N=100                  22.35 MB
    M0-5 AI 压测 N=200                  23.46 MB
    M0-5 AI 压测 N=300                  26.13 MB
    M0-5 AI 压测 N=400                  23.40 MB
    M0-6 首包变体（构建产物，非运行时）  不适用

    【实测结论】当前 JS 堆峰值区间为 **14.9 ~ 28.1 MB**。

5.2 GPU 内存【未测】
    Chrome 未向页面暴露 GPU 显存占用，M0 **无法测得**该指标。
    须在 M8 用 Chrome DevTools 的 Memory 面板手工核查。
    在此之前，**禁止**对 GPU 内存做任何数值承诺。

5.3 内存强制要求（不依赖未测项）
    - 关卡切换后必须释放上一关卡资源（须实测内存回落）
    - 禁止无限增长的缓存，必须有上限与淘汰策略
    - 新增常驻资源必须说明内存占用估算与释放时机


第 6 章  资源交付与验收流程
--------------------------------------------------------------------------------
6.1 流程
    美术/音频产出 -> 规格自检 -> 技术接入 -> 性能实测 -> 验收通过入库

6.2 强制要求
    - 未通过规格自检的资源一律退回，不得接入
    - 每批资源接入后必须立刻跑性能基线，贴出接入前后的内存与帧率对比数字
    - 超标资源当场退回，不接受"先接进去再优化"
    - 必须实测资源加载耗时，确保进入单局加载仍 ≤ 6 秒

6.3 命名与目录规范（强制）
    - 统一命名规范，禁止中英混用与拼音命名
    - 按"首包 / 关卡包 / 按需包"分类存放
    - 所有资源带版本号

6.4 验收标准
    - 凡本文档标注【实测】或【派生】的项，按数值验收
    - 凡标注【待定】的项，**在补测填实之前不得作为验收依据**，
      仅可按"暂按建议上限控制"执行，并记录为待复测项
