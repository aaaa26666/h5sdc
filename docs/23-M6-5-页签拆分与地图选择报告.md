## 三、设计与守住的不变式

| 不变式 | 落地 | 为什么必须这样 |
|---|---|---|
| **`config` 仍是默认地图的视图** | 新增 `deriveMap(mapId)`（记忆化）+ `configForMap(mapId)`；`config` 本身一字不动 | 大量工具与单测读 `config`（含 `capture-level-golden.mjs` 的几何黄金基准）。改它的形状等于把一批无关的东西一起炸掉。附带发现：黄金基准工具早就靠 `{...config, map}` 覆盖那五项来切图 —— "按图取视图"在工具侧已存在，这次只是搬进产品代码，**不是新增第二套机制** |
| **每张注册地图都过同一套校验与派生** | 启动期对 `MAP_TABLES` 里**每一张**图跑 `deriveMap` + `validateMap` | 玩家可以选图之后，"选了一张没被校验过的图"的后果是**进战区才崩**（或更糟：几何非法但能跑）。这些是手写坐标，启动期带坐标报错远比事后倒推便宜 |
| **地图判据只有一份** | 新增 `src/core/mapView.js` 的 `resolveMapId`（已注册 / 回落），档案收敛与 DEV 夹具共用它 | 两处各判一次就会出现"夹具说合法、档案收敛说非法" |
| **本局的地图只读一次并快照** | `main.js` 有 `mapCfg()`；进局的 kit 与将要建的世界**同属一张图** | 局内若再读档案里的 `mapId`，DEV 夹具/将来功能改了它就会出现"配装属于 A 图、世界建在 B 图" |
| **两图收益不可比** | `windowRaidsPerMap: 20`，各图独立判定；样本带 `mapId`，旧样本兜底 `(unknown)` | 单层 22 个容器 vs 两层 89 个。全局窗口按图切分后每张图只剩约 10 局，会把随机波动当结论 |
| **不留死入口** | 预设条以外的旧入口全部清掉；`#btnStart` 只留一个 | 留一个"看起来还能用"的重复入口，玩家会以为在哪一页点都一样 |

### 3.1 `windowRaidsPerMap` 这个数字是**量出来的**，不是拍的

> 全局窗口是"最近 20 局"（两张图交错），按图切分后每张图只剩约 10 局 —— 用 10 局样本判通胀/通缩
> 会把随机波动当成结论（**实测：同一份模拟数据下 `industrial_01` 被误报 `deflation`，
> 而它的全样本中位数完全正常**）。它必须 ≤ `maxSamples`，否则档案里永远凑不满窗口、
> 判定恒为 `insufficient`（一条**永远为假**的检查）。

配套两条启动期校验：必须是正整数、必须 ≤ `maxSamples`。第二条的理由值得单独记：
**一条永远为假的检查比没有检查更糟** —— 它会让"样本不足"这条守卫永远不触发。

## 四、端到端覆盖（父会话复核时逐条核对）

| 断言 | 它守的失效模式 |
|---|---|
| 点地图卡片**真的换了图**（写进档案，不是只改界面） | "只改了高亮"的假实现 |
| 本局快照里的 `raidMapId` 与档案一致 | 配装属于 A 图、世界建在 B 图 |
| 本局的**容器数 / 撤离点数 = 所选地图**的数字 | 标签换了但世界还是默认图 |
| 刷新页面后仍是那张图 | 只存内存、没随档 |
| **合法 id 不会被记成修复** | 收敛对好数据也动手（"检查乱报"与"检查不报"同样有害） |
| 未注册 id 回落**并留下痕迹**；写坏档案再加载也能收敛 | 坏档 / 外部篡改 |
| 收尾把地图恢复默认 | 测试之间的相互污染 |

## 七、诚实说明

### 7.1 没做到

- **真人试玩仍是零次**：地图卡片的信息密度、"选完图再看简报"这条动线是否顺手、
  **"进战区"从标题栏搬进页签后多一步点击**是否可接受 —— 全部只有判断，**没有手感依据**。
- **难度选择未做**（已裁定推迟）：不是"做了但隐藏"，是**根本没写**（难度相关字段一个都没有）。
  代价是**不同水平的玩家面对同一个 AI 密度**。
- **分图经济未按图配置**（登记 `M6-TEMP-9`）：两张图共用一套 `raidTargets`，
  工业区理论中位 1803 贴着下限 1800，判定会长期在 ok / deflation 边缘摆动。
- **局内没有任何"我在哪张图"的提示**：玩家在局内除了地形无从确认（简报只在局外）。
  不在本次需求内，但它是"选图"这个功能的一个可感知缺口。
- **地图卡片没有缩略图、没有"上次打这张图的结果"**：只有纯文字数字，视觉层次无设计评审。
- **`windowRaidsPerMap = 20` 没做统计功效分析**：它是从"档案最多留 60 局"与"20 局才够判"两条定的。
  真正的做法是给出"给定分布下，中位数差多少才能被判出来"的曲线。
- **`--only` 过滤仍是"组名子串匹配"**（`docs/20` §八 已登记）：本批次的新组被迫起名
  「★ M6-5 / **M5-5** 地图选择…」才不会被 `--only=m5` 跳过。这是同一处权宜的**第二次**使用，
  说明它不是偶发：正确的修法是让过滤器认**段落**而不是认名字。代价很具体 ——
  **新组一旦忘了带 `M5` 字样就会被静默跳过，而静默跳过比报错更难发现**。

### 7.2 实现者主动交代的"比看上去更脆"的地方（照录，因为这类自我披露最值钱）

| # | 脆弱点 | 性质 |
|---|---|---|

| 3 | **便携版新断言最弱**：只断言"至少 2 张卡片、恰好 1 张 on"，守的是"生产构建里界面没坏"，**不守内容** | 断言强度 |
