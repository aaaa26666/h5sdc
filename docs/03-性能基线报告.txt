第 0 章  本报告的性质（必须先读）
--------------------------------------------------------------------------------
0.1 这是"引擎与方法论基线"，不是"游戏性能承诺"
    本报告全部数据来自**M0 阶段的一次性验证场景**（等价几何场景、AI 压测场景、
    音频探针），**不是真实游戏**。真实游戏包含武器、特效、UI、动画、音效、
    关卡内容，性能必然不同。

    因此：
      - 本报告可用于**判定引擎可行性**与**建立复测口径**
      - 本报告**不得**用于对外承诺游戏帧率
      - 真实游戏的性能基线须在 M7（资源替换）与 M8（优化）后重新建立

0.2 数据可信度分级
      【实测】 有可复现数据，计时器分辨率已验证
      【派生】 由实测推算，附推算过程，待验证
      【未测】 明确缺口，不得引用

第 2 章  测量口径与已验证的测量陷阱
--------------------------------------------------------------------------------
2.1 指标定义
    avgFps          采样窗口内帧数 / 窗口时长
    frameP50/P95/P99 逐帧间隔的分位数
    low1Fps         最慢 1% 帧的平均帧时间折算出的帧率
    cpuP50/P95      step() 回调自身的 CPU 耗时（不含 GPU 异步完成时间）
    frameP95→预算   16.67ms=60fps，22.22ms=45fps，33.33ms=30fps

2.2 判定原则（重要）
    **性能判定以帧时间与 CPU 耗时为判据，不以 FPS 为判据。**
    原因见 2.3。

2.3 已在 M0 验证并修复的测量陷阱

    陷阱 1：本机显示器 165Hz，vsync=on 锁的是 165 不是 60
      实测表现：three 与 babylon 的 avgFps 均精确为 165.01 / 165.02。
      后果：该 FPS 无法用于比较引擎，只能说明两者都未跑满。
      处理：测试台增加 capped 标记，被锁帧的行改用帧时间判定。

    陷阱 2：vsync=off 且不同步 GPU 时，测的是 CPU 提交吞吐
      实测表现：frameP95 ≈ cpuP95（three 0.9≈0.8ms，babylon 4.4≈4.1ms）。
      后果：得到的 1253 / 500 fps 不能表述为"可达到的帧率"。
      处理：增加 --sync on（每帧 gl.finish()）路径用于测真实 GPU 耗时；
            AI 压测统一以 cpuP95 为判据。

    陷阱 3：Chrome 默认把 performance.now() 精度限制到 100µs
      实测表现：AI 压测中 pf 与 los 的每帧耗时全部量成 0。
      处理：静态服务加 COOP/COEP 开跨源隔离，**分辨率实测恢复到 0.005 ms**。
            每次实测回读 timerResMs 作为自检。

    陷阱 4：低于计时器分辨率的操作必须用批量微基准
      实测表现：单次视线射线 93ns，逐次计时无法测量。
      处理：window.__benchMicro() 批量执行 N 次再相除。
            这是 AI 结论的权威数据来源。

    陷阱 5：AI 成本是尖峰型，P95 会把尖峰平均掉
      实测表现：100 Agent 错峰重规划时每帧寻路 P95 量成 0，
                但最坏帧为 1.85 ms。
      处理：必须同时报告 max。

    陷阱 6：等价场景存在无法消除的不可比项
      阴影算法（PCFSoft vs PCF）、材质模型（Standard vs PBR）、
      粒子点尺寸单位。已记录，不掩盖。


第 3 章  实测数据汇总
--------------------------------------------------------------------------------
3.1 引擎等价场景基线【实测】
    场景：120 单位地面 + 200 静态障碍 + 150 动态物体 + 400 粒子 + 阴影(1024)
    条件：Three.js，pixelRatio=1

    条件                          数值
    ------------------------------------------------------------
    vsync=on  avgFps              165.01      （被 165Hz 锁住）
    vsync=on  frameP50 / P95      6.1 / 6.2 ms
    vsync=on  cpuP95              2.45 ms
    vsync=on  heapPeak            14.89 MB
    vsync=off avgFps              1253.25     （实为 CPU 提交吞吐）
    vsync=off frameP50 / P95      0.7 / 0.9 ms
    vsync=off cpuP95              0.8 ms
    vsync=off heapPeak            28.14 MB
    engineInitMs                  11.4 ms
    sceneBuildMs                  4.7 ms
    firstFrameFromNavMs           371.8 ms

3.2 AI 寻路与同屏数量【实测】
    单次操作成本（批量微基准）：
      A* 单次查询                 0.0184 ms（平均路径 25.5 格）
      流场单次全图重算            0.0718 ms（2304 格，与 Agent 数无关）
      视线检测单次射线            0.000093 ms

    每帧成本构成（CPU 节流 1x，中位数）：

      Agent  帧CPU P95   渲染P95    AI合计    AI占比   寻路最坏帧
      --------------------------------------------------------------
      50     1.61 ms     1.58 ms    0.04 ms   2.4%     1.96 ms
      100    2.18 ms     2.11 ms    0.07 ms   3.1%     3.00 ms
      200    2.61 ms     2.45 ms    0.16 ms   6.1%     5.66 ms
      300    3.05 ms     2.82 ms    0.23 ms   7.6%     8.17 ms
      400    3.28 ms     2.99 ms    0.29 ms   8.9%     9.68 ms

    每帧成本构成（CPU 节流 6x，模拟低端 CPU）：

      Agent  帧CPU P95   渲染P95   寻路最坏帧(A*)   寻路最坏帧(流场)
      --------------------------------------------------------------
      50     16.84 ms    16.19 ms  9.46 ms          —
      100    21.67 ms    20.59 ms  21.44 ms         —
      200    24.24 ms    20.53 ms  44.95 ms         2.01 ms
      400    22.55 ms    18.06 ms  68.29 ms         2.38 ms

    关键结论：AI 占帧 CPU 的 2.4%~8.9%，**渲染占 91%~98%**。
    A* 与流场的最坏帧差 20~30 倍（68.29 vs 2.38 ms）。

3.3 首包体积【实测】
    变体                              首包 raw    首包 gzip   首包 brotli
    ----------------------------------------------------------------------
    full（整个 three 全量保留）       720.2 KB    180.8 KB    146.8 KB
    named（命名导入最小集）           524.4 KB    130.0 KB    106.7 KB
    ns（命名空间导入）                524.4 KB    130.0 KB    106.7 KB

    已确认：命名空间导入与命名导入**体积完全相同（差 0 KB）**。
            tree-shaking 实际收益上限仅 40.1 KB brotli。
            代码侧首包地板 = **106.7 KB brotli**，占 30MB 预算的 0.35%。

3.4 音频行为【实测】

    ------------------------------------------------------
    AudioContext 初始 state     suspended       suspended
    AudioContext 创建耗时       29.92 ms        43.22 ms
    ctx.resume() 无手势         **永不 settle**  **永不 settle**
    <audio>.play() 无手势       NotAllowedError NotAllowedError
    手势后 state                running         running
    手势后 play                 played          played
    解锁总耗时                  15.69 ms        25.39 ms
    解码 30s 立体声 WAV         60.44 ms        59.07 ms

    音频参数：sampleRate 48000 Hz，baseLatency 0.01（10 ms），outputLatency 报 0。
    格式支持：MP3/AAC/OGG Vorbis/OGG Opus/WebM Opus/FLAC/WAV 均 "probably"。

3.5 内存【实测】
    JS 堆峰值区间：14.89 ~ 28.14 MB（各场景实测值见 3.1 与 3.2）。
    增长趋势：AI 数量从 50 增至 400 时，堆峰值 20.28 → 23.40 MB，增长平缓。
    GPU 显存占用：**未测**（Chrome 未暴露该指标）。

第 5 章  基线结论
--------------------------------------------------------------------------------
5.1 引擎可行性：成立
    Three.js 在目标机上可稳定支撑 M0 定义的等价场景复杂度，
    帧时间远低于 60fps 预算，引擎层面不存在阻断性问题。

5.2 性能瓶颈的位置：渲染，不是 AI
    实测渲染占帧 CPU 的 91%~98%，AI 仅 2.4%~8.9%。
    **M1 起优化预算应优先投向渲染与几何合批，而非 AI。**

5.3 最大的单点风险：A* 的同步尖峰
    6x 节流下 N=400 时单帧寻路 68.29 ms，会造成 1~4 帧可见冻结。
    必须按 M0-TECH-01 约束 C-1/C-2 实现查询预算限流。

5.4 第二个必踩的坑：音频解锁
    `await ctx.resume()` 在无手势时永久挂起，无异常无超时。
    必须按约束 C-7/C-8 实现音频解锁门。

5.5 首包：代码不是问题
    代码侧仅 106.7 KB brotli，占预算 0.35%。资源侧未测。

5.6 已建立的复测能力（M0 最重要的可复用产出）
    测试台已具备：等价场景规格表驱动、CDP CPU 节流、软件渲染模拟、
    GPU 同步开关、帧预算判定、页面错误捕获、批量微基准、
    计时器分辨率自检、结果落盘 JSON/CSV。
    以上能力可在 M7/M8 直接复用，用于建立真实游戏的性能基线。

第 7 章  M0 阶段的客观局限（如实声明）
--------------------------------------------------------------------------------
1. **所有数据来自合成验证场景**，不是真实游戏。真实游戏性能必然不同。
2. **首包指标无法在 M0 验证**，因为占 99.6% 的资源尚不存在。
3. **最低配置结论无法产出**，因为本机是高性能开发机，
   且 CDP 节流只模拟慢 CPU、不模拟慢 GPU。
4. **仅覆盖 Chromium 系**（Chrome + Edge），Firefox 与 Safari 完全未测，
   而《流程文档》9.4 兼容矩阵要求覆盖。
5. **未做任何长时稳定性测试**（30 分钟内存泄漏、长时间运行帧率衰减）。
6. **AI 场景行为极简**：只含寻路、视线、直线移动，
   不含动画、射击、状态机、感知记忆。真实 AI 成本会高于本报告。
7. 本次 AI 扫描**第一次遗漏了 --pf 维度**（跑的全是 A*），已补测；
   未补测的组合不得据本报告推断。
