## 三、四条需求的落地与证据

### ① 旋转过的物品拖起来保持旋转后的形状

根因：视图同时暴露**已定向**的 `w/h`（渲染用）和**未旋转**的 `baseW/baseH`（拖拽用），
`shapeFor(src, rotated)` 拿了前者再转一次 —— 于是拖起来的幽灵是"转了两次"的形状。

修法：`shapeFor` 一律按 `baseW/baseH` 算（没有 `baseW/baseH` 的来源，如装备格，仍按 `w/h`，不回归）。

- 单测：3 条（保持 / 取消旋转 / 无 baseW 的来源）+ **注入自检**（按旧实现复算，结果不同）。
- 端到端：**在拖动中途**读幽灵形状（不是松手后）→ `{rotated:true, shape:{w:4,h:2}}`；注入自检同组。

### ② 估值一律取整

`valueReadout(def, units)` / `valueReadoutOf()` 在 `core/items.js`，**只在"显示给人看"的那一层取整**，内部计算仍精确。

- 单测用 `1100/60 × 7` 这种**确实产生浮点噪声**的夹具（先断言原始值不是整数，再断言读数是整数）。
  刻意不用 `33.33×3` 那种凑巧整除的用例 —— 它永远为真，等于没有检查。

### ③ 大厅全屏

`index.html`：`.card.lobby { width: min(1500px, 98vw); max-height: 96vh; overflow: auto; }`。
端到端断言：卡片 1254×826 / 视口 1280×860（宽 ≥ 90% 视口）。

### ④ 网格内容与拖放

- 四张网格都画出来（背包 / 弹挂 / **保险箱** / 仓库），保险箱那张**局外可见**。
- 仓库 → 背包：网格多一份、仓库少一份（**不是复制**）。
- 背包 → 仓库：同理可逆。
- ± 步进器**已删除**；`tools/smoke.mjs` 的静态源码扫描把 `ammoInc|ammoDec|consInc|consDec|setAmmo|setConsumable`
  列为**禁用**（此前是豁免），并带注入自检。
- 拆分：在一格堆叠上点选后出现「拆分」按钮，弹窗输入数量；断言总量守恒。

## 五、缺陷登记（本次发现并修复）

> 格式沿用 `docs/13-M6-缺陷修复记录.md`。定位：`grep -rn "M6-BUG-0[678]" src/ tools/`。

### M6-BUG-06（S2）：背包明明是空的，却只带得进第一样东西

| 项 | 内容 |
|---|---|
| 编号 | **M6-BUG-06** |
| 分级 | **S2** —— 不崩、不丢档；但"往背包里放第二样东西"这件事**实际不可用** |
| 发现于 | M6-4 全量端到端（医疗组「急救包 0 → 0」、携行具组「自带 0 格」） |
| 位置 | `src/core/carry.js` 的 `findCarrySlot` |

**现象**：`grantTestKit` 依次往背包放弹药、手枪弹、绷带、急救包 —— 实测只有**第一样**进去了，后三样全部 `count=0`。
端到端表现为"按 4 用不了急救包""换弹从网格里扣不到子弹"，而失败信息看起来像"医疗/换弹坏了"。

**根因**：

```js
const grid = carryOccupancy(carry[name] || [], { [def.id]: def }, spec);   // 旧写法
```

只把"待放的这一件"的 def 传进占用图，而 `carryOccupancy` 对查不到 def 的条目是 `continue`
—— 于是**网格里已经放着的其它东西在占用图上不存在**，找出来的落点与它们重叠。
它**不报错**：找位成功，`carryAddAt` 随后用完整表复核判"重叠"并拒绝，调用方只看到"放不进去"。

**为什么此前没被抓到**：纯逻辑单测里"放东西"那几条都是**显式给坐标**（`carryAddAt(..., 0,0, ...)`），
从不走 `findCarrySlot`；而走 `findCarrySlot` 的场景（战利品入库、旧档迁移）在旧口径下
`loadout.ammo` 是空的，网格也是空的 —— 第一样总能成功，恰好掩盖了它。

**修复**：`findCarrySlot` 改为接收**完整的 itemDefs**（第 4 个参数），两个调用点同步改。

**证据链**：

| 环节 | 证据 |
|---|---|
| 缺陷真实存在 | 修复前探针实测：`grantTestKit` 返回 `[{ammo_556:120},{pistol_mag:0},{bandage:0},{medkit:0}]` |
| 修复有效 | 单测新增 3 条（第一件 / **第二件不同物品** / 两件不重叠）+ 端到端医疗组与携行具组转绿 |
| **注入自检** | 用旧调用（只给单件 def）复算 → 落点与第一件重叠、`carryAddAt` 拒绝 → 断言红 |
| 全量 | 单测 631/631、端到端 342/342 |

### M6-BUG-07（S2）：在大厅摆好的一包子弹，点"进入战区"时被上一局的账清掉了

| 项 | 内容 |
|---|---|
| 编号 | **M6-BUG-07** |
| 分级 | **S2** —— 玩家的东西凭空消失，且**没有任何提示** |
| 发现于 | M6-4 全量端到端（携行具组）与临时探针 |
| 位置 | `src/main.js` 的 `settleInterruptedRaid` → `src/core/settlement.js` 的 `applyRaidToProfile` |

**现象**：上一局没走完就刷新 / 关页面 → 重新在大厅摆好背包 → 点「进入战区」→ **背包与弹挂被清空**。

**根因**：补结算（M4-7）发生在**下一局开始之前**（点提示看结算、或直接点进战区），
而快照的口径恒为**未撤离**（`checkpointToFacts` 写死 `outcome:'death'`）。
于是 `settleCarryAfterRaid` 照"阵亡"处理，把**当前**网格 —— 也就是玩家刚为下一局摆好的那一份 —— 清空。

M6-4 之前这条路径影响很小（"带什么"是每次进局自动摆的，清了重摆即可）；
网格变成**玩家持久的安排**之后，它就成了静默丢东西。

**修复**：`applyRaidToProfile` 新增 `input.interrupted`。补结算时**不跑网格账**，
只把快照里真正保住的（保险箱那几件，`checkpointToFacts` 已按 `inSafe` 切好）直接入库。
上一局身上的其余东西当时已随页面消失，没有别处可退 —— 那不是"少退了"，是它已经不在了。

**证据链**：

| 环节 | 证据 |
|---|---|
| 缺陷真实存在 | 探针复现：点 `#btnStart` 前网格 2 盒弹药 → **250ms 后** `carry.backpack=[]`；localStorage 里 `h5_extract_raid_checkpoint` 仍在 |
| 修复有效 | 单测「补结算**保留**玩家为下一局摆好的网格」转绿 |
| **注入自检** | 去掉 `interrupted` 标记（走常规结算路径）→ 网格确实被清空 → 断言红 |
| 全量 | 端到端 342/342 |

### M6-BUG-08（S3，测试缺陷）：撤离点"开局就开放"是**占位值**，不是判定结果

| 项 | 内容 |
|---|---|
| 编号 | **M6-BUG-08**（测试 / 可观测性缺陷，不是玩法缺陷） |
| 分级 | **S3** —— 不影响玩法；但会把"还没判定"读成"判定说它开着"，产生假的失败信号 |
| 发现于 | M6-4 全量端到端（M4-BUG-01 killsAfter 组） |
| 位置 | `src/gameplay/extract.js`（zone 初值）、`tools/smoke.mjs`（断言时机） |

**现象**：断言「开局（0 杀）未开放」读到 `open=true`、`remainingKills=undefined`、`kills=0`。

**根因**：`zones` 构造时给 `open` 的是一个"常驻"**占位**（为避免第一帧读到 undefined），
第一帧 `update` 才换成 `evaluateOpenRule` 的结果。而占位**少了 `remainingKills` 字段** ——
于是"还没求值"与"规则说不需要击杀"在读数上长得一样。断言在首帧之前读快照，测的是时序。

**修复**（两处都要有，缺一不可）：

1. 初值补齐 `remainingKills: null`，并新增 `evaluated` 标志 —— 形状与 `evaluateOpenRule` 的返回值**逐字段一致**，
   "未求值"因此可辨识。
2. 端到端等 `evaluated === true` 之后再断言，并把它写进同一条断言（读到的必须是判定结果）。

这不削弱断言：等完之后照样要求 `open === false && remainingKills === 3`。

**证据链**：单测新增 2 条（规则求值的每个分支都给全 5 个字段 / 构造时的占位也是同一形状）；
端到端该组由 FAIL 转 PASS。

## 六、顺带修掉的一处工具口径（不是缺陷，是过期）

`tools/validate-loot-tables.mjs` 的「起始携行件确实占格」一直读旧的 `planCarry`（它读的是
**已删除**的 `loadout.ammo` / `consumables` 数字账）→ 恒为 **0 件**，即这条检查**从写下那天起就恒红**。

改为与运行时同源：`carrySpecs` + `carryAudit` 判定**表里写好的起始网格坐标**，占格按 `itemShape` 算。

> 凡"表里存一份、运行时派生"的东西，解析实现必须放进 `core/` 供两边共用。
